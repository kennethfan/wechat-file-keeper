# 不建立持久化索引

每次启动都重新全量扫描，不落任何数据库。

本机 `msg/` 共 14735 个文件，对全部文件做一次 `stat` 耗时 **0.51 秒**。在这个量级上，持久化索引带来的收益接近于零，而代价是三块实打实的复杂度：索引与磁盘的失效检测、微信自身增删文件后的增量对账、以及索引损坏后的恢复路径。

更关键的是，索引一旦存在，就会诱使人把「上次扫描的结果」当成真相呈现给用户——而微信文件随时在变。全量扫描的结果永远与当下磁盘一致，这个性质比速度更值钱。

## Consequences

- 若将来账号库增长到十万级文件、扫描超过 3 秒，此决定应被重新审视（届时可先做 stat 并发化，再考虑索引）。
- 内存中持有全部条目（约 14735 条），常驻内存量在几十 MB 量级，可接受。
