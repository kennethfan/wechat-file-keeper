# 移入废纸篓用 rename 实现，不调 Finder

macOS 上把文件放进废纸篓有两条路，实测结论如下（探针文件验证）：

- **`osascript` 调 Finder 删除**：在正常环境下成功，返回 `document file X of item .Trash`，文件确实离开原目录。
- **直接 `rename` 到 `~/.Trash/`**：同样成功，无需任何权限授予。

两者都能把文件送进废纸篓，但 Finder 路线要驱动 Apple Events，每次执行都要过自动化授权，且在不同环境（终端、沙箱、自动化代理）下行为不一致——本次开发中它在受限环境里就直接返回 `-10004 权限违例`。而 `rename` 是纯文件系统操作，行为可预测。

我们决定**用 rename 到 `~/.Trash/` 实现移入废纸篓**，并在应用数据目录写一份 JSON 清单（原路径、新路径、时间、字节数），作为撤销与审计的依据。

代价是废纸篓里没有「放回原处」按钮——macOS 只对 Finder 移入的项目保留该项元数据。补偿方式是清单本身：`wechat-file-keeper undo` 能按清单把文件移回原位。

## Consequences

- 撤销能力由本工具的清单保证，而非系统；清单丢失则无法自动还原（但文件仍在废纸篓里，可手动拖回）。
- 目标文件与 `~/.Trash` 必须同卷，否则 rename 退化为跨卷复制。微信容器与家目录默认同卷，跨卷时工具应报错而不是静默复制。
